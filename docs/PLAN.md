# DripLab 全体計画

## 1. プロダクト概要

### 一言

> スタバ・丸山・ドトール・タリーズ・カルディの豆データと、今日の気分から、**買う豆**と**淹れ方**を提案する。

### ユーザーストーリー

1. ユーザーがスライダーで「今日の気分」を入力する
2. 使える抽出器具（ドリップ / フレンチ / エスプレッソ / サイフォン）を選ぶ
3. アプリが **チェーン名・商品名・購入リンク** と **抽出レシピ** を提示する
4. （任意）結果を気に入ったら保存（MVP は localStorage）

### 技育博向けデモ（90秒）

1. 「眠いけど午後は集中したい」→ スライダー操作
2. 器具: ハンドドリップ（V60）を選択
3. 結果: 「カルディ ○○ブレンド」+ 水温 92℃ / 粉 15g / 240ml / 2:30 など
4. 別の気分 preset をワンタップで切り替え → 提案が変わる

## 3. スコープと現実的な折衷

5 チェーン全部 × スクレイピング × 8/26 は**タイト**です。審査通過と展示デモの安定性のため、以下の **ハイブリッド方式** を採用します。

```
[公式サイト] ──スクレイピング──► [raw JSON] ──正規化──► [beans.json]
                                      ▲
[手動シード CSV/JSON] ────────────────┘  ← 展示・審査用フォールバック
```

| レイヤ | 内容 |
|--------|------|
| **Must（8/26）** | 5 チェーン各 3〜5 豆、計 15〜25 商品。ゲスト Web デモ。スライダー → 提案 |
| **Should** | スクレイパー 5 本（更新可能）。購入 URL 付き |
| **Could** | 抽出レシピの細かいチューニング、履歴、LLM による説明文 |
| **Won't（今回）** | ログイン、店舗注文提案、在庫リアルタイム連動 |

**重要**: エントリー審査では「資料が見れない・動画が見れない」が主な落ち理由。データ件数より **デモ URL の安定性** を優先する。

## 4. 気分スライダー（案）

MVP では **4 軸**（各 0〜100）。未確定のため [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md) 参照。

| 軸 | 低い | 高い | レコメンドへの影響 |
|----|------|------|-------------------|
| **覚醒度** | リラックス | シャキッと | カフェイン・焙煎度 |
| **酸味** | 酸味少なめ | 酸味好き | 産地・浅煎り寄り |
| **コク** | すっきり | しっかり | ボディ・深煎り |
| **甘さ** | ビター寄り | 甘み・ナッツ | 焙煎・抽出時間 |

器具選択（複数可）:

- ハンドドリップ（V60 等）
- フレンチプレス
- エスプレッソ
- サイフォン

---

## 5. レコメンドの流れ

```
スライダー(4軸) + 器具
        ↓
  気分ベクトル → 理想コーヒープロファイル（酸味・コク・カフェイン・焙煎度）
        ↓
  全チェーン豆カタログとスコアリング（コサイン類似度 or 重み付き距離）
        ↓
  Top1 豆 + 器具別抽出レシピ（ルールベース）
        ↓
  代替案 2 件（他チェーン）
```

詳細: [RECOMMENDATION.md](RECOMMENDATION.md)
